# R5/R6 structural migration

## Scope

Migration only: no circuit algorithm, recovery policy, or signing admission was
changed. M1 is pending. The nonminimal signing example remains a regression test
of the old behavior; it must be deliberately revised when M1 is implemented.
No manuscript was imported or rewritten, and no license, Git tag, or DOI was set.

## Mapping

- R5 arithmetic -> src/quantum_ec/circuits/arithmetic/.
- R5 encodings and point updates -> src/quantum_ec/circuits/points/.
- Circuit builder -> src/quantum_ec/circuits/order_finding/.
- Classical group operation and scalar multiplication -> classical/curve.py.
- Continued fractions and accepted denominators -> recovery/continued_fractions.py.
- Selected gcd accumulation and budget -> recovery/.
- Historical trial-factoring certification -> baselines/trial_recovery.py.
- Basis propagation and Fourier distributions -> simulation/.
- Count models and MCX lowering -> resources/.
- Experimental signing equations -> signing/signature.py.
- Entry points -> experiments/scripts/ (invoke with python -m).
- Benchmark curve/signature -> experiments/reference/, exposed to tests through
  tests/reference/. Encoded-point expectations -> tests/reference/encoding.py.
- Basis-test helpers -> tests/support/. Tests are split by run cost/type.
- Historical notes -> docs/history/; historical TeX -> paper/drafts/.
- Historical reports -> results/legacy/; NPZ arrays -> its ignored raw/ folders.

## Traceability

migration_manifest.json maps every original top-level function/class to its
new path, with before/after AST hashes. 146 of 155 bodies are identical.
Nine differences are six CLI path/directory changes, two mock target strings,
and one instrumentation hook retargeted after splitting modules. Scientific
function bodies and circuit builders are unchanged. Imports necessarily differ.
pre_migration_hashes.json records all 100 original input files.
historical_artifacts.json records 20 copied reports/notes/arrays byte-for-byte.
Historical artifacts were NOT regenerated by this migration.

## Validation environment

Dedicated environment: CPython 3.11.5, Qiskit 2.0.0, NumPy 2.1.3,
pytest 8.3.5. The user's global Python was not modified. Transitive dependencies
were freshly resolved; requirements-lock.txt is a migration lock, not a claim
about the complete historical environment. Package editable installation passed.
All 51 discovered runtime submodules imported without legacy sys.path additions.

## Checks and limits

See results/migration/summary.json for machine-readable test results.
Quick inherited checks and selected arithmetic/statevector tests were run on
both the legacy and migrated code. Scaffold and package-boundary checks are
additional and do not constitute mathematical circuit validation.

Saved p29 measurements were replayed: at T=4, 100 exact recoveries and 100
matching verified signatures, with signature (1,4). This is a replay, NOT a new
propagation of all Q=2048 arithmetic inputs.

The initial full runs were interrupted in the expensive p29 scalar-chain test.
A later independent validation supplied by the author completed all 134 tests:
29 quick, 104 other slow tests, and the p29 Q=32 chain. The supplied slow logs
were inspected and preserved; see validation_followup.md. These results refer
to the migrated snapshot BEFORE the shared-recovery maintenance described there.
A fresh Q=2048 circuit run was not performed by that follow-up.
Qiskit's existing MCX pending-deprecation warnings were observed, not suppressed.
The Linux GitHub Actions workflow first ran on GitHub for commit c4edfbd (quick
tests, success); see results/full-validation/summary.json.
